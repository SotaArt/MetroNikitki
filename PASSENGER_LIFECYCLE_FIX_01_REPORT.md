# Отчёт: восстановление движения пассажиров (PASSENGER_LIFECYCLE_FIX_01)

## 1. Изменённые файлы

- `src/App.tsx` — точечные правки в `WaitingPassengers` (шкала времени и расчёт индивидуальной задержки старта).
- `src/styles.css` — точечная правка позиционирования свободно перемещающихся пассажиров.

`src/game/logic.ts` и `src/game/types.ts` **не изменялись**.

## 2. Какие именно ошибки исправлены

1. **CSS-позиционирование пассажиров (ряды вместо свободного размещения):**
   - Ранее `.free-passenger` задавал `position: absolute`, но более позднее правило `.passenger-wrap` устанавливало `position: relative` (одинаковая специфичность), из-за чего элементы попадали в поток и выстраивались рядами.
   - Добавлено правило `.passenger-wrap.free-passenger { position: absolute; }`, чтобы для свободно перемещающихся пассажиров гарантированно применялось абсолютное позиционирование. Позиционирование остальных `.passenger-wrap` не менялось.

2. **Несовместимость временных шкал (`Date.now()` и `requestAnimationFrame`):**
   - `spawnMs/releaseMs` создавались от `Date.now()`, а сравнение выполнялось с `ts` из `requestAnimationFrame` (другая шкала отсчёта), что блокировало переход из ожидания в движение.
   - Время появления/старта переведено на монотонную шкалу `performance.now()` и сравнивается с `ts` из RAF в одной шкале.

3. **Накопление задержки старта из-за глобального `spawnOrder`:**
   - Убрано влияние `spawnOrder * 800` на `releaseMs` (глобальный счётчик появления больше не определяет индивидуальное время старта).
   - Индивидуальная задержка старта теперь вычисляется отдельно для каждого пассажира и не зависит от количества/добавления/удаления других пассажиров.

## 3. Как теперь рассчитывается время старта

- При первом обнаружении пассажира в UI фиксируется `spawnMs = performance.now()` (момент появления сущности в визуальном контуре).
- Из индивидуального `seed` пассажира детерминированно берётся значение RNG (`r1.value`, 0..1) **без общего RNG**.
- Индивидуальная задержка: `startDelayMs = 300 + r1.value * 900` (диапазон **300–1200 мс**, детерминированно от seed).
- Время старта: `releaseMs = spawnMs + startDelayMs`.
- `releaseMs` не зависит от глобального `spawnOrder`, не зависит от числа ранее появившихся/удалённых пассажиров и не пересчитывается в течение жизни пассажира.
- Последовательность появления пассажиров сохраняется существующей логикой спавна в игре (`src/game/logic.ts`, без изменений), движение предыдущего пассажира на появление следующего не влияет.

## 4. Как обеспечено абсолютное позиционирование

- В `src/styles.css` добавлен селектор `.passenger-wrap.free-passenger { position: absolute; }` (достаточная специфичность поверх `.passenger-wrap { position: relative; ... }`).
- Сохранены `left`, `top`, `transform: translate(-50%, -50%)`, размеры/оформление и структура обёртки (облачко остаётся позиционированным относительно элемента пассажира).
- Контейнер платформы `.platform-rows` уже имеет контекст позиционирования (`position: relative`), дополнительные изменения контекста не потребовались.
- Координаты применяются инлайн-стилем (`left/top` в %) внутри `.platform-rows.free-move`.
